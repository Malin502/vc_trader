# Step 2a 報告: 高時間軸ゲート G1〜G3 の評価

事前登録 `gate-preregistration-2026-11-20.md`（敗因分解の結果を見る前）に基づく評価。
候補は G1/G2/G3 の 3 つ、SMA は 50/200 固定、閾値探索はしていない。

## 実装

- `aivc_trade/strategy/gates.py`: 1h 足から日足（UTC 日次の終値）を集計し、各 1h バーに
  「**エントリー日の前日まで**の最後の確定日足」での判定列を付ける（当日終値は不使用＝先読みなし）。
  SMA 未確定（NaN）期間はゲートしない。
- `aivc_trade/strategy/signal.py`: レジーム判定の直後に G1/G2/G3 を適用。`entry.mode` とは独立。
- `aivc_trade/backtest/simulator.py`: ゲート有効時のみ日足を集計。既定（全 false）は現行と同一挙動。
- 単体テスト `tests/test_entry_gates.py`（18 件）。既存 298 件と合わせて全緑。

## 読み方（要点）

- G1/G3 は USDT の 2022 をほぼ（G1）／完全に（G3）止め、通期 PF を 0.91 → 1.00 前後、
  最悪窓 MaxDD を -30.7% → -17.5/-18.6% に半減させた。窓 PF>1 は 36.5% → 52.4%/49.2%。
- ただし改善の実体は「2022 を取らない」こと。2021-22 を除くと baseline PF 1.290 に対し
  G1 1.304 / G3 1.265 で、上昇相場での選別能力は上がっていない。2024 は G1/G3 とも
  建玉入替でマイナス（+2,924 → -1,112 / -1,852）。
- G2 は 2022 を止めるが 2023-26 の勝ち玉も大量に落とし、通期 PF 0.83・窓 PF>1 15.9% で不合格。
- JPY 窓は G1 が PF 1.77 → 1.20 と悪化（2025-26 の押し目を落とす）。G3 は PF 1.85 と僅かに改善するが
  純損益は +15,238 → +11,432 で、PF 改善は建玉入替の偶発で説明できる範囲。
- 事前登録どおり 3 候補のみ・閾値探索なし。PBO 0.59（USDT）は「4 本の差はほぼノイズ」を含意する。

## live / shadow 実装（2026-11-20 照合）

ライブ用の初期実装（Claude 席パッチ）を評価側の意味論に突き合わせて移植した。
食い違いは評価側に揃え、評価側が規定していない点は元の選択を残した。

| 項目 | Step 2a 評価（正） | 初期実装（パッチ） | 一致 | 揃え方 |
|---|---|---|---|---|
| 日足の境界 | UTC 0:00（1h 足を `resample("1D").last()`） | UTC 0:00（Binance `1d` 足） | 一致 | そのまま（データ源だけ違う） |
| SMA の基準 | 終値のみの単純平均 200 | 終値のみの単純平均 200 | 一致 | そのまま |
| 終値 == SMA | 止めない（`close >= sma` が通過） | 止めない（`close < sma` で停止） | 一致 | そのまま |
| 判定に使う足 | 前日までの最後の確定日足（当日終値は使わない） | 確定日足のみ＋**欠損・期間不足・NaN・取得失敗はブロック（fail-safe）** | **不一致** | 評価側に合わせ **ゲートを開く**（`ok=False` で記録・警告のみ） |
| BTC 系列 | `reference: BTC` を銘柄リストから解決（USDT 評価は BTCUSDT / JPY 評価は BTCJPY）。1h parquet 由来 | BTCJPY（Binance `1d`） | 一部不一致→裁定で確定 | ライブの基準は **BTCJPY** に固定（評価の USDT 側は BTCUSDT だが実戦データで統一） |

- 実装: `aivc_trade/strategy/htf_gate.py`（`evaluate_g3` / `G3Tracker`）、`generate_signals(htf_gate=...)`、
  `main_live.py`（起動時取得＋日次更新、`signal_journal.record_gate`）、`ops/shadow.py`（`on_bar(htf_gate=...)`）。
- 設定: `htf_gate.g3`（live / shadow 用・既定 false）。`gates.*` はバックテスト専用のまま
  （live は判定列を作らないため、有効にすると fail-safe で全停止する。起動時に警告を出す）。
- 検証: 実データ（BTCJPY 1h parquet と Binance 1d）で直近 400 本の 1h バーを突き合わせ、
  評価側の判定列と live 側の判定が **0 件不一致**（blocked 157 / open 243）。
- テスト: `tests/test_htf_gate_g3.py`（11 件）。既存 357 件と合わせて 368 件すべて緑。

## 残作業

- 実板ペーパーへの結線: `config.paper.yaml` で `htf_gate.g3.enabled: true` にすれば有効になる
  （既定 false）。有効化の判断は照合結果を踏まえて行う。
- データ欠損時は評価側の意味論どおり「ゲートを開く」。取得失敗が続く間は無防備になるため、
  GATE ジャーナル（WARNING）と Discord 通知で検知する運用にする。ブロック側に倒すかは別途裁定。
- JPY の日足 SMA200 は 2024-09-27 からしか確定しない（XRP は 2024-11-15）。2024-05〜09 は G1/G3 が効いていない。
- CSCV は 4 試行・月次リターンでの概算のみ。試行数を増やす場合はブロック長と指標の妥当性を再検討する。
